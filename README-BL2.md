# Borderlands 2 (Switch) on Android — build & run notes

This tree is the **DM NVN HLE port framework** (originally the Divinity: Original Sin 2 port) built with
`DM_GAME=bl2`. It contains **code and tools only**: no game data, no shaders, no APK, no saves.

> **游戏资源（romfs / DLC / 补丁）不在本仓库，也不应上传到 GitHub。**
> 请使用你自己卡带 dump 出来的游戏文件。把商业游戏资源提交到公开仓库会违反 GitHub 的版权政策，
> 也可能导致仓库被封禁；体积上也放不下（BL2 资源为数十 GB 级）。

## 0. Legal / game data

This repository ships **code and tools only**: no game data, no decryption keys, no
firmware, and no APKs or shader packs built from them.

- Dump from hardware you own. Do **not** share the dump, the generated `*.xgs` shaders, or
  APKs/data packs built from them.
- Whether decrypting and converting your own copy for personal use is permitted depends on
  where you live; check your local law.
- This project does not host or link to ROMs, keys, or warez.

Same position as other emulator/port projects: Ryujinx — “It does not include Nintendo
firmware, keys, or commercial games. You must obtain those files by dumping hardware you
own.”; nx2android — “Dump both from your own Switch, and don't share them or the APKs and
data packs built from them.”

## 1. What you need

- Windows PC (build host) + an Android 11+ arm64 phone
- **Your own** Borderlands 2 (Switch) dump: `romfs/WillowGame/CookedSwitch`, `aoc/`, patches
- Python 3, JDK 21, Android SDK (build-tools + platform-tools), Gradle 9.x
- .NET 10 SDK — only if you build the shader translator (`dmsh_xlate`, `net10.0`)
- (native build) Android NDK — the gradle config uses `ndkVersion 29.0.14206865`
- A GPU that can run the title; this port was only validated on **Adreno**

## 2. Data layout on the phone

```
/sdcard/Download/Borderlands2Mobile/
  romfs/WillowGame/CookedSwitch/...   # from your own dump
  aoc/...                             # DLC content (if you own it)
  patch-cn/...                        # optional translation patch overlay
  dm/shaders/*.xgs                    # generated by you (see §4) — NOT in this repo
  dm/env                              # runtime switches (see §3)
  saves/                              # your saves
```

### What must be there, and what can be deleted

The APK is only the host. A folder that actually boots needs the items marked **required**:

| Path | Needed for | Can a build reproduce it? |
| --- | --- | --- |
| `romfs/`, `aoc/` | **required** — boot and assets | No. Your own dump. |
| `dm/out/{main,sdk}.patched.bin` + `*.fixups.tsv`, `*.gates.tsv` | **required** — the host loads these at boot | **Yes** — `dm/tools/patch_nso.py` with `DM_TARGET=android`. Re-running it produces byte-identical output (verified by SHA-256 against the reference dump). |
| `dm/shaders/*.xgs` | **required** — rendering | Yes, from the dump (`bl2_shader_jobs.py` + `dmsh_vk_xc2.py`, §5). Missing ones can be dumped at run time, but that is a long loop. |
| `dm/env` | optional | Hand-written; the defaults are fine. |
| `patch-cn/`, `patch-res/` | optional — localization | No. Third-party overlays (§6). |
| `saves/` | optional | No. |
| `dm/capture/`, `dm/dump/`, `dm/spv-dump/`, `vk-pipeline-*.bin`, `snap/`, `logs/`, `cheat.*`, `probe.*`, `pushed.txt` | nothing | No. Runtime debug output and caches; delete freely. |

`tools/setup_bl2.ps1` runs the first two reproducible steps in order (patch the program, then
translate the shaders) and assembles `dm\out` + `dm\shaders` into one folder:

```powershell
$env:DM_PYTHON = 'C:\path\to\python.exe'   # Python 3.10+ with capstone and lz4
powershell -File tools\setup_bl2.ps1 -Exefs <dump>\exefs -Decoded <dump>\decoded `
    -GlobalCache <dump>\GlobalShaderCache-Switch.bin -OutDir <phone-dm>
```

It expects the ExeFS modules (`main`, `sdk`, NSO) to be extracted already; it does not unpack
NSP/NSZ packages.

## 3. `dm/env` — verified configuration

```
DM_SF_SERVE=hid
DM_ROMFS_OVERLAY=/sdcard/Download/Borderlands2Mobile/patch-cn
DM_AOC_OWNED=1
DM_GFX_SLOTS=3
DM_VK_PRESENT=mailbox
DM_GFX_MID_CHUNK_US=2000
DM_PRESENT_MAX_HZ=240
DM_BL2_WIDE_PRESENT=1
DM_LOG=0
DM_3D_SCALE=1.0
DM_GYRO=1
```

- `DM_BL2_WIDE_PRESENT=1` — present at the screen aspect instead of the 16:9 window.
- `DM_LOG=0` — **log switch**: no `boot.log`, no logcat forwarding, no `logs/logcat.txt`
  (the native crash marker `dm-crash.txt` is kept). Set to `1` when you need logs.
- `DM_3D_SCALE=1.0` — the game's built-in 3D render scale. The port defaults it to `0.75`
  on phones; `1.0` = the Switch original, sharper but heavier. `0.9` / `0.85` are good
  middle grounds. `DM_3D_SCALE_DYN=0` disables the automatic drop on dropped frames.
- `DM_GYRO=1` — six-axis sensor from the phone's gyroscope (tilt/gyro aiming). Unset is
  on; `DM_GYRO=0` turns it off. XC2/D3 default to off in the code.
- `DM_VK_DRIVER`, `DM_3D_SCALE`, `DM_*` are all documented by their use sites under `dm/host`.

## 4. Build the APK

**First build: the generated headers (`DM_GEN_DIR`).** The Android host build needs a
directory with four files derived from game data, so they are not committed:
`dm_vault_tab.h`, `dm_hud_exp.h`, `dm_bright_levels.inc`, `dm_touch_native_art.c`.

**The DOS2/D3 generators in `dm/host/Makefile` do not work on BL2.** They read
`romfs/data/build_manifest.psv` and `romfs/global/excel/*.txt`, which the BL2 RomFS does not
contain; run against a full BL2 dump, all of them stop with `FileNotFoundError`.

What does work — and what the published APK is built with — is the stand-in set in
`.github/workflows/build-apk.yml`, in the `Generated host headers (DM_GEN_DIR)` step. Create
a directory, save those four files from that step verbatim (`dm_bright_levels.inc` is empty),
then point the build at it:

```powershell
$env:DM_GEN_DIR = 'C:\path\to\gen'
```

`tools/build_apk.ps1` passes it to gradle as `-PdmGenDir` (without it, CMake stops with
"要 -DDM_GEN_DIR=..."). The stand-ins define empty tables that load from `dm/derived.tsv` at
run time when that file exists; for BL2 they stay empty, and that is how the release APK runs.

```powershell
$env:ANDROID_HOME = 'C:\path\to\android-sdk'
$env:JAVA_HOME    = 'C:\path\to\jdk-21'
$env:GRADLE       = 'C:\path\to\gradle\bin\gradle.bat'
$env:DM_GAME_NAME = 'bl2'
$env:DM_APP_ID    = 'org.bl2.port'
$env:DM_APK_NAME  = 'BL2-port'
powershell -NoProfile -File tools/build_apk.ps1 -Install <adb-serial>
```

Output: `work/BL2-port-debug.apk`, also copied to `dist/`.

## 5. Shader bundles (the part that is NOT in this repo)

**First build the translator.** `XLATE` must point to the built executable of the C# project
`dm/gfx/tools/dmsh_xlate` (`TargetFramework net10.0`; it references the bundled Ryujinx
sources in `dm/third_party/ryujinx`):

```powershell
dotnet build dm/gfx/tools/dmsh_xlate/dmsh_xlate.csproj -c Release
# -> dm/gfx/tools/dmsh_xlate/bin/Release/net10.0/dmsh_xlate(.exe)
```

`SPIRV_OPT` and `SPIRV_VAL` are the `spirv-opt` / `spirv-val` binaries from a SPIRV-Tools
build (the Android NDK ships them under its shader tools directory).

The game's shaders are compiled for NVN/Maxwell and must be translated offline into
`<key>.xgs` bundles, one per shader, placed in `dm/shaders/`. None of that output is
committed (`.xgs` is in `.gitignore`; it is derived from game data).

The pipeline has four steps, and step 1 is the one people miss:

1. **Decode the UE3 packages.** BL2 stores them Oodle-compressed and only the game's own
   decoder can read them, so the decoder is run once out of the game:
   ```bash
   python tools/bl2_oodle_job.py build work/bl2/oodle/job <package.xxx>...
   # then run the app once with DM_OODLE_JOB=<abs path to work/bl2/oodle/job>;
   # hle_oodle.c replays the decoder right before nnMain, writes job.out and exits
   python tools/bl2_oodle_job.py rebuild work/bl2/oodle/job.out work/bl2/oodle/job.json work/bl2/decoded
   ```
2. **Collect shader records** from the decoded packages plus `GlobalShaderCache-Switch.bin`:
   ```bash
   python tools/bl2_shader_jobs.py work/bl2/decoded <GlobalShaderCache-Switch.bin> work/bl2/shaders-jobs
   ```
3. **Translate** to `<key>.xgs` (`XLATE` = the translator built above, plus `SPIRV_OPT` / `SPIRV_VAL`):
   ```bash
   XLATE=... J=8 python dm/gfx/tools/dmsh_vk_xc2.py work/bl2/shaders-jobs work/bl2/shaders-xgs
   ```
   To redo only some keys, pass them after the output directory:
   `... dmsh_vk_xc2.py <jobs> <out> <key1> <key2> ...`
4. Push `*.xgs` to `dm/shaders/` on the phone and restart the game.
5. Anything still missing is dumped at runtime to `dm/missing/<key>.rec`
   (only while `DM_LOG=1`). The dump is a bare record without its `jobs.tsv` metadata, so the
   practical fix is to re-run steps 1-3 — the package already contains that shader.

Notes learned on this title:

- Some vertex programs are **two-part** (part A writes position, part B writes the rest).
  Translating A alone makes every pixel pipeline fail on Adreno; `dmsh_vk.py:vertex_ab`
  merges them. Keep that on.
- Some merged vertex programs were rejected by the Adreno compiler; running
  `spirv-opt -O --preserve-bindings` on the final module fixed the pipeline build.
- A few programs need a depth (clip-space z) correction; that is a per-title rule,
  not a generic translation step.

## 6. Localization overlays (`patch-cn`, `patch-res`)

The Chinese translation and the resource patch on the phone are **overlays**, not build
output: they are the game's own data files with localized text, mounted over `romfs/` via
`DM_ROMFS_OVERLAY`. This repository does not produce or distribute them, and they must not
be committed — supply your own.

| Directory | Contents |
| --- | --- |
| `patch-cn/` | `WillowGame/SwitchTOC.txt`, `WillowGame/CookedSwitch/{Coalesced_INT.bin, Startup.xxx, Startup_LOC_INT.xxx}`, `WillowGame/DLC/Switch/<pack>/Compat/{toc.txt, Localization/INT/*.int}` |
| `patch-res/` | a single replacement `WillowGame/CookedSwitch/Coalesced_INT.bin` |

Put them under `Download/Borderlands2Mobile/` and select one at a time:

```
DM_ROMFS_OVERLAY=/sdcard/Download/Borderlands2Mobile/patch-cn
```

Point it at `patch-res` instead if that is the patch you want. Only one overlay is active at
a time, and removing the line restores the untouched game data.

## 7. Validation status / disclaimer

Validated only on: **realme RMX8899, Snapdragon SM8845, Adreno 829, Android 17**.
Other GPUs, drivers, Android versions and resolutions are **not guaranteed**: shader
modules may be rejected by a different driver, performance/thermal headroom differs,
and touch layout / save paths may need adjustment. Treat this as a reference port.

## 8. If the build fails

| Symptom | Cause | Fix |
| --- | --- | --- |
| CMake stops with `要 -DDM_GEN_DIR=...` | `DM_GEN_DIR` not set | use the CI stand-in headers (§4) |
| `No .NET SDKs were found` | only the .NET **runtime** is installed | install the .NET 10 **SDK** |
| `net10.0 is not supported` (NETSDK1045) | older SDK | `dmsh_xlate.csproj` needs .NET 10 |
| `XLATE=<executable> is required` | translator not built, or `XLATE` unset | `dotnet build dm/gfx/tools/dmsh_xlate/dmsh_xlate.csproj -c Release`, then set `XLATE` (§5) |
| `spirv-opt` / `spirv-val` not found | `SPIRV_OPT` / `SPIRV_VAL` unset | point them at the NDK `shader-tools/<host>/` binaries |
| `patch_nso.py` aborts on a registered cut | the NSO is not the expected build (wrong dump or a modified one) | use an unmodified dump of this title |
| Gradle: `SDK location not found` | `ANDROID_HOME` / `local.properties` missing | set `ANDROID_HOME` (§4) |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | the APK is signed with a different key | uninstall the old app once — saves live in `Download/Borderlands2Mobile/saves` and are not removed |
| App starts, then black screen; log says `out/main.patched.bin` missing | `dm/out` was not pushed | run `tools/setup_bl2.ps1` and push `dm/out` (§2) |
| Boots but the picture is missing / empty surfaces | shader bundles missing | translate `*.xgs`; with `DM_LOG=1` the missing ones are dumped to `dm/missing/*.rec` |
| Crashes on boot on an untested GPU | driver or GPU not supported | try another `DM_VK_DRIVER`, attach the logs (§7) |

`tools/setup_bl2.ps1 -SkipShaders` is the quickest way to check whether the first two required
items are correct before spending time on a full shader translation.

## 9. Frame rate, buffering and per-device settings

**60 FPS is the target, not a guarantee.** Only Adreno 7xx / 8xx has been validated. Mali
(Exynos, Dimensity, Tensor), Xclipse and PowerVR are untested and may sit at 30-45 FPS, or
fail to boot at all.

| Setting | What it does | Trade-off |
| --- | --- | --- |
| `DM_3D_SCALE` | 3D render scale, 0.5-1.0 (default `0.75` on phones). UI and text stay sharp | lower = more FPS, softer 3D picture |
| `DM_3D_SCALE_DYN` | steps the scale down automatically when frames are dropped (on by default) | `=0` pins the scale |
| `DM_GFX_SLOTS` | frame-slot ring: `2` (default) or `3` | see below |
| `DM_VK_PRESENT` | `fifo` (default: the queue waits for the display), `mailbox`, `immediate` | mailbox / immediate avoid queue stalls |
| `DM_PRESENT_MAX_HZ` | caps present pacing: 30 / 60 / 90 / 120 | 30 runs cooler and steadier on weak phones |

**Double vs triple buffering (`DM_GFX_SLOTS`)**

- `2` (double buffering, the default): one frame resource fewer, the cheapest in memory, but
  the CPU has to wait for the GPU to finish with the previous slot before recording the next
  frame. Frame times are less even, so dips are more visible.
- `3` (triple buffering): while frame N is being recorded, frame N-2 is still on the GPU, so
  CPU translation and GPU rendering overlap. Frame times are smoother; the cost is one extra
  frame's worth of GPU memory and bandwidth.
- `4` is accepted but not recommended — the returns stop and memory pressure grows.

Rule of thumb: **3 slots on anything with headroom, 2 slots when GPU memory is tight or the
device is already GPU-bound.**

**Starting points per device class** (a starting point, not a measurement — tune per phone):

| Device class | `DM_3D_SCALE` | `DM_GFX_SLOTS` | `DM_VK_PRESENT` | Expectation |
| --- | --- | --- | --- | --- |
| Snapdragon 8 Gen 2 / 3, 8 Elite (Adreno 740+) | `1.0` | `3` | `mailbox` | locked 60 |
| Snapdragon 888 / 8 Gen 1, 7+ Gen 2 / 3 | `0.85`-`0.9` | `3` | `mailbox` | 60 with occasional dips |
| Snapdragon 778G / 7 Gen 1 / 6 Gen 1 | `0.75` | `2` or `3` | `fifo` | 40-60 |
| Older or low-end Adreno | `0.6`-`0.7` | `2` | `fifo`, `DM_PRESENT_MAX_HZ=30` | 30-45 |
| Mali / Xclipse / PowerVR | `0.6`-`0.7` | `2` | `fifo` | untested; may not boot |

If the frame rate is unstable but the GPU is not pegged, try `3` slots first; if the device
gets hot or the picture stutters more, go back to `2` and lower `DM_3D_SCALE`.

## 10. Visible rendering problems

Symptom → cause → fix, from what this port actually ran into.

### Light shafts are missing or black

A light shaft is a separate additive pixel program. Without its bundle the beam does not draw,
or draws black.

1. Set `DM_LOG=1`, reproduce, and look for `missing shader <key>` in the log and
   `dm/missing/<key>.rec`.
2. Re-run the shader pipeline (§5) so that key gets a bundle, push, restart.
3. If the bundle exists but the beam is still black, it is usually the two-part vertex program:
   keep `vertex_ab` merging on and re-translate — translating part A alone makes every pixel
   pipeline in that group fail on Adreno.

### Muzzle flash or tracers missing, or drawn as a black quad

Same class: an additive/particle pixel program with no bundle, or one whose depth behaviour
depends on the clip-space z fix.

1. Same triage as above.
2. Make sure the module went through `spirv-opt -O --preserve-bindings`; without it the Adreno
   compiler rejects some modules and the effect disappears.

### Part of a DLC map is completely black

This is the "DLC shaders were never translated" case, not a broken level.

- The base RomFS and `aoc` are separate package sets. A pipeline run over the base packages
  alone leaves the DLC programs out, and only the DLC surfaces stay black.
- Fix: run steps 1-3 of §5 over the DLC packages as well, then merge the resulting `*.xgs` into
  `dm/shaders` — the key namespace is the same, so a plain copy is enough.
- Confirm with `DM_LOG=1`: DLC-only keys show up in `dm/missing/` only when no bundle exists.

### Two rules that save time

- A **missing** bundle means missing geometry or effects; a **wrong** bundle means garbage or a
  rejected pipeline. The log distinguishes them, so read it before re-translating everything.
- After any shader change, delete `dm/vk-pipeline-cache.bin` and `dm/vk-pipeline-list.bin` on the
  phone; otherwise stale pipelines keep being reused and the fix looks like it did nothing.
